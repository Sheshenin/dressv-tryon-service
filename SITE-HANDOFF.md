# Dress V в WooCommerce. Передача агенту сайта БМК

Сверено 21 ноября 2026 года. Dress V работает в закрытом режиме для администраторов на карточке [«Красный костюм со шляпой»](https://best4event.ru/product/красный-денди/), товар `200`. Плагин версии `0.1.4` установлен на рабочем WordPress. Hermes настроен на реальный OpenAI Images Edits. Владелец подтвердил, что генерация работает.

## Где вести изменения

- **Dress V.** Репозиторий [Sheshenin/dressv-tryon-service](https://github.com/Sheshenin/dressv-tryon-service), ветка `main`. В [wordpress/dressv-try-on](wordpress/dressv-try-on/) лежат PHP плагина, JS интерфейса и CSS. В [wordpress/pilots/red-dandy.json](wordpress/pilots/red-dandy.json) находится готовый пример настройки товара с безопасным значением `mock` для новой установки. Серверное API и адаптеры провайдеров находятся в `src/dressv`.
- **Сайт БМК.** Репозиторий [Sheshenin/bmk-rental-site](https://github.com/Sheshenin/bmk-rental-site), ветка `main`. На сервере проект расположен в `/data/projects/bmk-rental-site`. Плагин сейчас установлен в томе WordPress по пути `/var/www/html/wp-content/plugins/dressv-try-on` контейнера `bmk_rental_site-wordpress-1`. Настройки красного костюма хранятся в базе WordPress в опции `dressv_pilot`. Изменения сети и монтирований внесены в рабочий `compose.override.yaml`. Исходная копия на хосте лежит в `/etc/dressv-wordpress/compose.override.before-dressv.yaml`.
- **Синхронизация репозиториев.** Агент сайта должен сверить свою актуальную `main` с конфигурацией ниже и провести изменения через штатный процесс сайта. Зафиксируйте явную версию плагина из Dress V, например включите её в `app/plugins/dressv-try-on` и добавьте bind mount только для чтения, если это соответствует принятому способу доставки других плагинов сайта. Зафиксируйте конфигурацию Compose и операционные зависимости в репозитории сайта. Состояние активации и настройки товара перенесите штатным механизмом WordPress. Держите один основной источник кода, чтобы две копии плагина не расходились. Настоящая передача обновляет репозиторий Dress V. Ветка `main` сайта остаётся у сопровождающего агента.

## Как встроена примерка и что увидит пользователь

Плагин **Dress V Try-On** добавляет интерфейс через стандартный хук WooCommerce `woocommerce_before_add_to_cart_form`. Шаблон карточки и файлы темы при внедрении Dress V не редактировались. Хук должен вызываться шаблоном формы аренды. Для текущей темы `bmk-storefront` это выводит **«Примерить образ на себя»** прямо перед **«Арендовать»**, которую тема добавляет своим скриптом в форму.

Кнопки имеют одинаковые габариты и типографику. Примерка светлая с вишнёвой рамкой, аренда сплошная вишнёвая. В окне используются переменные темы БМК, тёплый светлый фон, Georgia в заголовке и Inter в основном тексте. CSS ограничен классами Dress V. При смене темы проверьте, что WooCommerce вызывает хук и обе кнопки идут в нужном порядке на телефоне и компьютере.

1. **Открытие.** Кнопка открывает нативное модальное окно. Администратор выбирает одно фото, которое видно в предпросмотре. После первой примерки можно выбрать следующее фото в той же форме.
2. **Ожидание.** После отправки окно показывает статус и анимированную полосу. Первые 15 секунд идут обратным отсчётом. Затем показывается прошедшее время. Ориентир в интерфейсе составляет около минуты. Готовность определяет ответ сервера.
3. **Результат.** PNG выводится рядом с исходным фото. Нажатие открывает полноэкранный просмотр без обрезки. Крестик и Escape возвращают в окно примерки. При смене входного файла очищается предыдущий результат.
4. **Защита.** Форма и AJAX-действие доступны только вошедшим пользователям с `manage_options` и только для настроенного товара. WordPress проверяет nonce и привязывает задание к текущей сессии. Браузер обращается к WordPress через `admin-ajax.php`, а PHP пересылает запрос на Hermes по проверенному TLS. Токен между серверами и ключ OpenAI отсутствуют в браузере. Результат отдаётся с `Cache-Control: no-store`. После получения PNG браузер подтверждает удаление. Без подтверждения Hermes очищает задание по TTL, 10 минут.

## Что перенести из рабочей конфигурации сайта

У WordPress нужны PHP 8.1 или новее, расширения cURL и Fileinfo и рабочий маршрут до `https://dressv-hermes.internal:18444`. Пример ниже показывает только добавления в существующий сервис `wordpress`. Сохраните остальные `volumes` и `extra_hosts` из актуального Compose сайта.

```yaml
services:
  wordpress:
    extra_hosts:
      - "dressv-hermes.internal:172.18.0.1"
    volumes:
      - type: bind
        source: /run/dressvuploads
        target: /run/dressv-uploads
        bind:
          create_host_path: false
      - type: bind
        source: /etc/dressv-wordpress/upload.ini
        target: /usr/local/etc/php/conf.d/zz-dressv-upload.ini
        read_only: true
        bind:
          create_host_path: false
      - type: bind
        source: /etc/dressv-wordpress/ca-cert
        target: /run/dressv-ca.pem
        read_only: true
        bind:
          create_host_path: false
      - type: bind
        source: /etc/dressv-wordpress/wordpress-token
        target: /run/dressv-wordpress-token
        read_only: true
        bind:
          create_host_path: false
```

- На хосте WordPress `run-dressvuploads.mount` монтирует `/run/dressvuploads` как `tmpfs` на 128 МиБ с `noswap`, `noexec`, `nodev` и `nosuid` до запуска Docker. Оба параметра PHP, `upload_tmp_dir` и `sys_temp_dir`, указывают в этот том. Клиентский портрет проходит через временный файл PHP и не добавляется в медиатеку.
- `dressv-wordpress-relay.socket` слушает только на внутреннем Docker-мосту по адресу `172.18.0.1:18444`. Узкое правило UFW `dressv-wordpress-relay` допускает вход с подсети моста. Реле передаёт TLS через существующий IPv6-канал. Проверка имени сертификата и CA идёт от PHP до Hermes. При пересоздании Docker-сети проверьте имя моста, сокет и правило UFW.
- Служба `dressv-https.service` на Hermes слушает отдельный порт `18444`. Вход ограничен адресом хоста WordPress и межсерверным токеном. Параметр `DRESSV_PROVIDER=image-edits` активирован в systemd drop-in на Hermes. Совместимый провайдер переключается там же через адрес, ключ и, при необходимости, имя модели. Значения секретов хранятся на серверах. В оба репозитория попадают только шаблоны и пути. [Развёртывание и откат](DEPLOYMENT.md) · [Настройка провайдера](OPENAI-SETUP.md)

Перед изменением Compose сравните нормализованный результат `docker compose config` до и после. Для штатного обновления сверяйте состояние сайта и контейнеров и сохраняйте доступ к исходному override. Отключить кнопку можно деактивацией плагина или удалением её опции после сохранения копии настроек.

## Что подготовить для каждой карточки

Нужны **отдельная конфигурация товара, подобранные референсы этого комплекта, индивидуальный промпт и критерии визуальной приёмки**. Отдельные PHP, HTML и JS для каждой карточки не нужны. Обычная галерея может включать альтернативные стилизации. Для генерации используйте явно отобранные ID вложений.

| Поле | Как подготовить | Проверка |
| --- | --- | --- |
| `product_id` | Найдите конкретный опубликованный товар WooCommerce. Зафиксируйте ID, название и ссылку. | Ссылка ведёт к правильному комплекту. ID действителен на целевом сайте. |
| `references` | Выберите от 1 до 4 локальных вложений в медиатеке, в нужной последовательности. Первым поставьте общий кадр. Затем дополнительные ракурсы или крупные планы, если они дают информацию о силуэте, слое, фактуре, головном уборе, обуви или аксессуаре. | Все кадры показывают именно выбранный комплект. Файлы доступны локально через WordPress. Снимок с другой стилизацией исключён. |
| `prompt` | Напишите индивидуальное задание на один постановочный кадр. Опишите роль портрета, роль каждого референса, весь видимый состав, детали, посадку головного убора, положение пояса и слоёв, кадрирование, свет и фон. | Промпт самостоятельно передаёт всё обязательное. Объём до 24 000 байт UTF-8. |
| `required_details` | Запишите наблюдаемые условия приёмки, например «широкий пояс поверх жакета на талии» или «видны вся корона и обе туфли». | До 32 строк по 512 байт UTF-8. Так можно вручную проверить, что модель сохранила детали. Сейчас генератор получает промпт, а сервер проверяет формат PNG. Автоматической оценки сходства и соответствия костюму пока нет. |
| `generation_mode` | Для рабочей карточки укажите `live`, когда Hermes настроен на реального провайдера. Значение `mock` подходит для тестовой установки. | Поле меняет подсказку в интерфейсе. Реальный выбор провайдера делается на Hermes. |

Поддерживаются **статические PNG, JPEG и WebP**, до 4096 пикселей по длинной стороне и до 12 Мп на изображение. Портрет и референсы вместе должны уложиться в 16 МиБ. Оставляйте запас для загрузки портрета. Дополнительный ракурс нужен, когда он показывает новую деталь. Избыточные ракурсы расходуют лимит и могут запутать модель.

### Рабочий порядок для агента каталога

1. **Снимите исходное состояние.** Откройте карточку, изучите описание, состав, варианты и всю галерею. Получите ID основного и дополнительных вложений через WooCommerce. Посмотрите сами изображения в достаточном размере и сопоставьте каждое с конкретным ID. По названию файла качество и состав определять нельзя.
2. **Зафиксируйте один образ.** Перечислите вещи, обувь, аксессуары, цвета, материалы, порядок слоёв и положение видимых деталей. Отметьте, что явно видно и что осталось за кадром. Если существенная деталь не подтверждается, найдите референс или запросите решение владельца карточки. Разные версии наряда готовьте отдельно. При необходимости добавьте в медиатеку недостающий съёмочный ракурс, а в галерею добавляйте его только если он нужен покупателю.
3. **Составьте промпт.** Изображение 1 всегда задаёт внешность человека. Изображения 2–5 в выбранном порядке задают одежду, обувь и аксессуары. Укажите, что лицо, волосы и поза каталожной модели не служат образцом внешности. Зафиксируйте состав и силуэт, затем постановку, освещение и кадрирование. Если обувь или головной убор важны, попросите кадр в полный рост с запасом сверху и снизу. Для неизвестной второстепенной детали задайте допустимое упрощение, если оно не меняет образ. Явно перечислите характерные ошибки для этого комплекта.
4. **Сохраните заготовку на товар.** Храните конфигурацию с ID, порядком вложений, промптом и критериями. В примечаниях к изменению укажите название, дату, версию, почему выбран каждый ракурс, какие снимки исключены и результат проверки. Снимки посетителей и результаты генерации сюда не записываются.
5. **Проверьте перед включением.** Проверьте читаемость файлов, MIME, размеры и запас общего лимита. В закрытом режиме убедитесь, что кнопка стоит перед арендой, гость не видит форму, авторизованный пользователь получает свой результат, полноэкранный режим закрывается, а аренда продолжает работать. Для визуальной приёмки используйте разрешённые тестовые фото с разным ракурсом, оцените сходство и каждый пункт `required_details`. Исправляйте промпт или состав референсов по конкретному дефекту. Случайную удачу одного кадра не считайте готовностью карточки.

### Как применить конфигурацию

Сейчас код читает единственную опцию WordPress `dressv_pilot`. Она включает **один товар за раз**. Подготовка JSON для следующих товаров не включает их автоматически. Для последовательного пилота сделайте резервную копию опции и примените конфигурацию выбранного товара через имеющийся WP-CLI или загруженное ядро WordPress, как описано в [инструкции плагина](wordpress/README.md). После проверки верните рабочий товар. Для нескольких одновременно доступных карточек реализуйте в плагине хранение конфигураций по ID товара, например проверяемые метаданные WooCommerce. Выбор параметров должен происходить на сервере после проверки товара и доступа. Перенесите текущий товар `200` при миграции и сохраняйте закрытый режим до отдельного решения о запуске.

**Образец для красного костюма.** Вложения `201` и `202` показывают один костюм с тигровой шляпой. Снимок `736` показывает версию с красным котелком и исключён. В промпте закреплены красные жакет и брюки, бронзово-золотистый трикотаж, тигровая шляпа, золотистая цепь, кольца и кеды. Верх шляпы и обе туфли должны попадать в кадр. Для рабочей карточки установлено `generation_mode: "live"`. [Полный промпт и критерии](wordpress/pilots/red-dandy.json)

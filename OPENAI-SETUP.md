# OpenAI API и кредиты Dress V

## Подтверждено 20 ноября 2026 года

В Personal Organization виден активный грант на $75 с остатком **$74,98** и сроком до 13 декабря 2026 года. В проекте Dress V включён действующий лимит **$5**, на момент сверки интерфейс показал расход **$0**. Эти цифры описывают состояние на дату проверки. Перед платным запросом нужно сверить их повторно. [Credit Grants](https://platform.openai.com/settings/organization/billing/credit-grants)

В `/etc/dressv` на Hermes есть отдельный токен WordPress и файлы TLS. Ключа OpenAI в этом каталоге нет. Адаптер `Images Edits` реализован и испытан с подменой HTTP-транспорта. HTTP-служба использует credential `CREDENTIALS_DIRECTORY/provider-api-key`. Адаптер отправляет портрет первым и не повторяет отправку вслед за сетевой ошибкой. Развёрнутая служба работает с тестовым провайдером. Платный запрос в рамках работ по этому репозиторию пока не выполнялся.

Текущий этап — техническая разработка вставного плагина WordPress/WooCommerce. Для технического прогона используем кредиты ChatGPT API и синтетические снимки. Клиентский запуск и обработка реальных фотографий относятся к следующему этапу.

## Общий транспорт на Hermes

Базовая служба стартует с `DRESSV_PROVIDER=mock`. Для подключения OpenAI установите [шаблон drop-in](deploy/dressv-provider.conf.example) как `/etc/systemd/system/dressv-https.service.d/60-provider.conf` и положите проектный ключ в `/etc/dressv/provider-api-key` с правами `0600` для root. Ключ передаётся через systemd `LoadCredential`. Для первого запуска адрес задан как `https://api.openai.com/v1/images/edits`, модель по умолчанию — `gpt-image-2.6-sunburst`. [Images Edits](https://developers.openai.com/api/reference/resources/images/methods/edit)

Для совместимого провайдера меняются `DRESSV_PROVIDER_ENDPOINT` и содержимое файла ключа. Если отличается имя модели, его задаёт `DRESSV_PROVIDER_MODEL`. Совместимость означает Bearer-аутентификацию, multipart Images Edits с несколькими входными изображениями и ответом с одним PNG в `data[0].b64_json`. Для другого формата потребуется адаптер на Hermes, HTTP API плагина остаётся прежним.

После изменения конфигурации выполните `sudo -n systemctl daemon-reload` и `sudo -n systemctl restart dressv-https.service`. При рестарте задания в памяти очищаются. Drop-in разрешает исходящие подключения провайдера, вход на порт 18444 продолжает ограничивать отдельная таблица nftables `dressv_https` и проверка адреса в приложении. Для возврата в тестовый режим уберите drop-in и перезапустите службу.

## Порядок подключения и проверки

1. **Сверить организацию и проект.** Открыть Credit Grants в Personal Organization и проверить срок и доступный остаток. Открыть Limits проекта Dress V и сверить действующий предел. [Настройки API-проектов](https://help.openai.com/en/articles/9186755-managing-projects-in-the-api-platform)
2. **Установить проектный ключ.** Создать ключ сервисной учётной записи проекта с минимальными правами и передать его только на Hermes безопасным путём. Подключить его через отдельный systemd credential `provider-api-key`. Межсерверный токен PHP применяется только для связи WordPress с Dress V.
3. **Выполнить один синтетический запрос с разрешения владельца.** Явно выбрать модель и ограничить число вызовов. Сверить расход по Usage проекта и Credit Grants организации. При неопределённом исходе запроса из-за таймаута разобраться с Usage перед любым повтором.
4. **Подтвердить обработку данных перед клиентским пилотом.** Срок жизни файлов в Dress V и PHP относится к нашей инфраструктуре. Для API нужно отдельно проверить регион, основание передачи, политику хранения и настройки проекта.

Для повторной привязки гранта используйте [инструкцию по API-кредитам ChatGPT](https://developers.openai.com/api/docs/guides/chatgpt-api-credits).
